# E8-B1B2 · 910B1 vs 910B2 同负载代际对比

> 同一脚本 `scripts/e8_micro.py` 在两块芯片各跑一遍。
> B1=远端 npt 容器（E8b 数据），B2=本机 davinci7（共卡：同卡有 55G 引擎，
> 对比含争用污染，下文标注）。

## 数据对照

| 指标 | 910B1 | 910B2（共卡） | 判定 |
|---|---|---|---|
| naive vs fused @S512 | 0.22→? | 0.141/0.073ms 1.93× | — |
| naive vs fused @S2048 | ~4× | 3.96× | 一致 |
| naive vs fused @S8192 | **5.32×** | **5.25×** | 一致 |
| decode matvec bs=1 | **1475 GB/s** | **1254 GB/s** | ⚠️ 见下 |
| batch256 matmul | 752 GB/s | 730 GB/s | 一致 |
| decode-vs-KV 长峰值 | ~999 GB/s | ~985 GB/s | 一致 |

## 解读（诚实口径）

- **融合算子加速比两代一致**（~5.3×）——FIA 收益是架构机制不是代际红利
- **bs=1 matvec B2 反而低 15%**：B2 实测时同卡有 57G vLLM 引擎在跑，
  HBM/AICore 被分走——这是**共卡争用污染**而非 B2 更慢；要干净的代际数
  需在 B2 独占时复测（遗留项）
- batch256 带宽两代一致（730 vs 752，3%）——batch 一大进入计算 bound，
  带宽敏感性消失，共卡影响也随之缩小
- 方法论价值：同脚本跨芯片跑 = 可移植 microbench；加 `--device` 和
  共卡标注就能复用——**对比实验的第一要务是声明争用状态**
