# N7: PD 分离在慢互联上的账本（分析实验，基于 N3/N4 实测数据）

PD 分离（Prefill/Decode Disaggregation）是 2026 面试必考架构题（DistServe/Splitwise/Mooncake 系）。本实验不做部署，用本机实测数据回答：**"这套架构搬到我们这台跨 NUMA PCIe 的 3 卡机上，账算得过来吗？"**——这比背论文结论高一个层级。

## 1. 输入数据（全部本机实测）

| 量 | 值 | 来源 |
|---|---|---|
| 跨 NUMA 卡间互联带宽（饱和） | **16.3 GB/s**（busbw，256MB all-reduce；PCIe Gen4 x16 理论的 51%） | N4 实测 |
| 互联固定延迟 | **288 µs**（1 元素 all-reduce，与消息 ≤256KB 无关） | N4 实测 |
| Qwen3.5-4B hybrid KV 斜率 | **32 KB/token**（8 attn 层 × 2 × 4 KV头 × 256 × 2B） | N3 实测六点吻合 |
| 同规模全注意力模型 KV 斜率 | 128 KB/token（4×） | N3 对照 |
| Qwen3.8-27B-w8a8 KV 斜率 | 64 KB/token（16 attn 层 × 2 × 4 × 256 × 2B） | N5 架构数据推算 |
| decode 单步时间（4B bf16） | ~96-114 ms（batch=1 eager） | N2/冒烟实测 |
| 4B prefill 吞吐 | ~2 765 tok/s（4096tk=1481ms） | N2 实测 |

注：N4 测的是 all-reduce busbw；PD 分离的 KV 传输是卡间单边拷贝，方向相同量级（跨 NUMA PCIe 路径），用作近似时**偏保守**（单播应略快于环）。已诚实标注。

## 2. 账本：传输一个请求的 KV 要多久

设 P 实例（卡 A）prefill 完成后把 KV 传给 D 实例（卡 B），跨 NUMA PCIe：

| 模型/上下文 | KV 体积 | 传输时间 @16.3GB/s | 对照：该模型一个 decode 步 | 传输 ≈ 几步 decode |
|---|---:|---:|---:|---:|
| 4B hybrid @ 8K | 256 MB | 15.7 ms | ~100 ms | 0.16 步 |
| 4B hybrid @ 32K | 1 GB | 63 ms | ~100 ms | 0.63 步 |
| 4B hybrid @ 128K | 4 GB | **250 ms** | ~100 ms+（长上下文更慢） | ~2.5 步 |
| 4B 全注意力对照 @ 32K | 4 GB | 250 ms | ~100 ms | ~2.5 步 |
| 27B w8a8 @ 32K | 2 GB | 125 ms | ~250 ms（待 N6 实测） | ~0.5 步 |

再加细粒度账：层级传输（Splitwise 式逐层搬运）每层 1/32：4B@32K → 每层 ~2ms，与单层前向计算（~3ms）同量级，**理论上可与下一层计算重叠**；但层级路径每层要跨卡同步，且 N4 实测小消息（≤256KB）有 288µs 固定税——4B 每层 KV=32KB 落在"纯延迟平台"，32 层 × 288µs ≈ **9.2ms 纯握手税**，比传输本身（63ms 总量摊到每层 2ms）还重 4.5 倍。

## 3. 结论

1. **DistServe 的前提在本机不成立**。DistServe 论文称"合理放置下 KV 传输可低于一次 decode 步"——其前提是 NVLink/PCIe 5.0。本机跨 NUMA PCIe 饱和 16.3GB/s：短上下文（≤8K）勉强成立（0.16 步），长上下文（≥32K，尤其 hybrid 模型的 128K 长文场景）传输达 1-2.5 个 decode 步，PD 分离的延迟收益被吃掉大半。
2. **PD 分离的吞吐公式**（T_PD = max(I/mP, O/nD) vs 融合式 (a+b)/(m+n)）只有在 P/D 各自独立调优（DP attention、expert 并行等）后才可能为正——否则分离纯亏（多一份模型副本显存 + 传输开销）。SGLang 文档原话："不做差异化优化，PD 分离吞吐反而更低"。
3. **本机 3 卡的最优分工不是 PD 分离**，而是：数据并行 3 副本（环境A E4 已验证的路线）或 1 推理 + 2 实验。PD 分离需要≥2 张高速互联卡做 P/D 对，本机跨 NUMA 拓扑（SYS，无 HCCS）天然不适合。
4. **hybrid 架构放大了 PD 分离的一个新难点**：GDN 层的 recurrent state（49.5MB/请求，fp32）不随长度增长但**不可部分回滚/截断**（TreeWY 论文），传输体积小但生命周期管理复杂——KV cache 可以按块传，S 矩阵必须整体原子交接。
5. 环境A 注脚：E7（PD 同卡共置建链失败定位）、E18（跨节点 PD 三层失败画像 + 静默垃圾输出）说明跨节点 KV 传输的工程脆弱性即使在 vllm 0.30 + 专业框架下也真实存在。

## 4. 面试讲法

"PD 分离什么时候值得？" → 我算过账：核心变量是 **KV 体积/互联带宽 vs decode 步时间** 的比值，以及 P/D 能否各自差异化调优。我在跨 NUMA PCIe（16.3GB/s 实测）机器上算过：32K 上下文传输 1GB 要 63ms ≈ 0.6 个 decode 步，加上小消息 288µs×层数的握手税，分离收益所剩无几；DistServe 的"传输 < 一步"结论依赖 NVLink/PCIe5。所以选型顺序是：先看互联拓扑（TP/PD 都吃高速互联），再看负载形状（长 prompt 短生成才利好分离），最后才是 P:D 配比调优（DeepSeek 生产 1:10 的前提是 H800 + 定制传输栈）。
