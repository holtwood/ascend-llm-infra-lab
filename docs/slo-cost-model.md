# SLO / 成本换算：把 bench 数字变成容量规划数字

> 面试原题："这台机器能撑多少 QPS？每百万 token 成本多少？p99 怎么拆？"
> 所有换算基于本仓库实测数据（E1/E2/E4/E8/E9），假设全部显式标注。

## 1. 容量：SLO 达标口径下的单副本 QPS

Qwen3.5-4B 单卡（910B2，util 0.92），sonnet 负载 in≈3500/out≈200：

| SLO | 达标并发上限 | goodput | 原始吞吐 |
|---|---|---|---|
| TTFT≤2s & TPOT≤100ms | c32 | **5.0 rps** | 651 tok/s |
| TTFT≤1s & TPOT≤100ms | c16 | 3.6 rps | 460 tok/s |
| TTFT≤4s & TPOT≤150ms | c64 | 6.3 rps | 807 tok/s |

**回答模板**：先问 SLO（TTFT/TPOT/端到端？p50 还是 p99 判定？），
再从 goodput 曲线峰值读容量，不报裸吞吐峰值。

容量上限的物理边界（E8）：KV 池 1.006M tokens ÷ 单请求 5.4k = ~185
并发会话硬顶；但**先撞的是调度器准入墙**（chunked-prefill token 预算），
所以实际并发远低于 KV 理论上限——容量规划两者都要算。

## 2. 成本：¥ / 1M tokens

假设（显式声明）：910B2 单卡综合成本 **¥25/小时**（≈$3.4/h，
按云端租价/资产折旧+电费折算的量级，非精确报价）。

- 单副本 4B @ SLO 内实测：out 807 tok/s（c64）→ **2.9M tok/h**
- 输出成本：¥25 ÷ 2.9M ≈ **¥8.6 / 1M 输出 token ≈ $1.2**
- 若把 prompt 计入（total 4035 tok/s）：14.5M tok/h → **¥1.7 / 1M 总 token**

对比口径（仅数量级参考）：GPT-4 级 API $5–30/1M 输出；
自建单卡 4B 便宜 1–2 个数量级但能力不同——**成本对比必须同模型档位**。

w8a8-27B 单卡：SLO 内（c8）out 149 tok/s → 0.54M/h → **¥47 / 1M 输出**；
c64 裸吞吐 396 tok/s 但 93% 违 SLO——按吞吐报价会把成本低估 14 倍。

## 3. p99 延迟分解（E1 c64 实测）

```
e2e p99 ≈ TTFT p99 (3.34s) + T_out × TPOT p99
TTFT p99 = 排队时间 + 分块 prefill (~1.3s@2048tok/in3500)
```

- c32→c64：TTFT p99 1.67s→3.34s——**增量几乎全是排队**，prefill 本体没变
- TPOT p99 ~150-160ms：decode 步间争抢，随 running 数近似线性恶化
- 排障定位法：TTFT p99 涨先看队列深度（num_requests_waiting）和
  KV 占用；TPOT p99 涨看 running 数和抢占计数（E8 已验证两路信号）

## 4. 扩容 / 选型决策的量化口径

- 加副本：E4 实测 N=3→4 吞吐 +0%（瓶颈在注入层）但 goodput 12.4→13.5rps
  ——**扩容决策看 goodput 增量 / 成本增量**
- 量化：w8a8-27B vs bf16-8B —— 同卡位下 27B SLO 内吞吐 149 vs 819 tok/s，
  单位成本差 ~9×，换来 QA +9.5pp（E6）——为精度付费的显式换算
- 调度参数是免费的容量：mnb 256→4096 同负载 goodput 0.02→3.06rps（E9），
  不花一分钱换 ~150× 有效产能

## 5. 一页速查（答辩用）

| 问题 | 数字 |
|---|---|
| 4B 单卡 SLO 容量 | ~5 rps（TTFT≤2s, sonnet 负载） |
| KV 硬顶 | ~185 会话（1.006M tok ÷ 5.4k/req） |
| 单卡输出成本 | ~¥8.6 / 1M out tok（¥25/h 假设） |
| p99 分解 | TTFT p99 主项=排队；TPOT p99 主项=running 争抢 |
| 扩容信号 | 吞吐平台 + goodput/达标率仍在涨 → 继续扩 |
| 停止扩容信号 | goodput 增量 < 成本增量（E4 N=3→4 已在拐点） |
