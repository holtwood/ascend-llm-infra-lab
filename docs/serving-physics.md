# Serving 物理总纲（Ascend 910B1 实测常数）

> 一份把"serving 为什么这样设计"讲成物理量级的文档。
> 所有数字都来自本仓 `results/overnight_20261105_160244/` 的真机测量
> （Qwen3-0.6B 真权重，910B1 单卡，CANN 9.0，torch_npu 2.10，eager）。
> 用途：面试被追问"为什么"时，直接给常数和推导。

## 1. decode 为什么慢：三道墙，按顺序撞

```
① 发射开销墙（batch 小、eager）：29ms/step，只有带宽天花板的 3.6%
        ↓ 解法：图捕获（ACLGraph/CUDA Graph）、算子融合
② attention 访存效率墙（长上下文）：KV 读 265 GB/s，HBM 峰值的 19%
        ↓ 解法：FlashAttention 式融合 kernel、paged-KV 内联寻址、KV 量化
③ 真实带宽墙：1412 GB/s（裸 matvec 已达到 94% 峰值）
        ↓ 到这一步才是"decode 是带宽受限"的教科书说法
```

面试用法：被问"decode 为什么慢"，先答"分三层"，再给三组数字。
绝大多数候选人只会答第 ③ 层。

## 2. 批处理经济学：短上下文 vs 长上下文是两种规律

| | 短上下文（512-2k） | 长上下文（8k-32k） |
|---|---|---|
| 步时随 batch | **几乎不变**（29ms @bs=1..64） | 随 batch 增长但每序列成本下降 |
| 每序列成本 | 不变（29ms） | **降 2.7-3.5×**（bs=64） |
| 瓶颈 | 权重读被摊薄 → 吞吐线性涨 | KV 读并行度提升 → 单请求延迟改善 |
| 含义 | 加 batch 换吞吐，不换延迟 | 加 batch 同时换吞吐和延迟 |

数字：短上下文 bs 1→64，tok/s 34 → 2204（64×）；长上下文 32k，每序列
511 → 191 µs（2.7×）。

## 3. 容量：并发数是上下文的倒数

`并发 = 可用HBM / (2 · 层数 · n_kv · d_head · 2B · ctx)`

0.6B/64GB 实测：2k → 271 路，8k → 68 路，32k → 17 路（公式与真分配完全吻合）。
推论：把上下文从 8k 砍到 2k 换 4× 并发；这也是"长上下文很贵"的定量含义——
**不是算得慢，是装不下**。

## 4. Prefill 与 Decode 的不对称（PD 分离的物理依据）

- prefill：算力受限，bs 1→4 得 4× 吞吐（15k → 60k tok/s），每 token 11.8µs
- decode：权重读受限，每 token **29,400µs**（bs=1）
- **每 token 差 250×** → 混跑时 decode 的长尾会被 prefill 洪峰打断

**干扰实测（E44）**：一个 8k 的 prefill chunk 会让并发 decode 延迟膨胀
**16-34×**（decode bs=1/8）；chunk 降到 512 则只有 1.25-1.41×。
换双流并发不改善（3.39× vs 串行 1.41×）→ 是真 SM/HBM 争用，
**所以同卡 PD 分离物理上收益有限，PD 必须有独立设备**（与 E18 互证）。

chunked prefill 的甜点（E34）：chunk=2048 时总 prefill 时间只多 13%，
但单步阻塞从 152ms 降到 43ms（干扰降 3.5×）。**关键地板：一个 prefill chunk
的延迟不可能低于一个 decode step（~30ms）**，因为两者是同样的发射开销。

## 5. 抢占：recompute vs swap 的交叉点（E32）

- swap 成本 = `2 × KV字节 / 20GB/s`（线性）
- recompute 成本 = 发射地板 + 线性 matvec + **二次 attention**
- 实测交叉点：**~4k token**；32k 时 swap 便宜 2.27×

vLLM 默认 recompute 的前提是"prefill 有图捕获（地板≈0）+ 融合 attention
（二次项常数小）"。这个前提一旦不成立（如本实验的 eager 栈），swap 更划算。

## 6. Prefix cache（APC）：收益由"省下的二次项"决定，不是命中率（E33）

| prefix | 命中率 | 单请求加速 |
|---|---|---|
| 512 | 80% | **0.85×（更慢）** |
| 2048 | 94% | 0.83×（更慢） |
| 8192 | 98% | **2.76×** |

短 prefix 时 APC 只多付 cat/mask 开销（发射地板已主导）；长 prefix 时省下
大量二次计算。**这解释了真实 vLLM 上"APC 开着中位数 TTFT +12%、p99 −55%"**：
收益集中在长 prefix 的尾部请求。

## 7. 一句话总结（面试收尾用）

> 在 Ascend 910B1 上，0.6B 模型的 decode 上限是 939 tok/s（HBM 94% 效率），
> 但 eager 实现只有 30 tok/s——差 31 倍，全部是发射开销。图捕获之后下一个
> 瓶颈是 attention 的 KV 访存效率（19% → 50% → 峰值）。容量上，8k 上下文
> 只能装 68 路并发，这是"长上下文贵"的真实含义。prefill 每 token 比 decode
> 快 250 倍，这个不对称就是 PD 分离存在的理由。
