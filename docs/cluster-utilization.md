# 四机利用模型 — 无 RDMA 集群的正确用法

> 背景：4 台 910B2（M3/M1/M2/D 各 1 卡），节点间仅 SSH 端口互通、
> 无 RDMA/HCCS 互联（E18 实测）。"把 4 张卡用满"在这个约束下
> 不是 TP/PP，而是三个正交维度 + 一个编排层。

## 维度一：副本级扩展（服务面）

- 4 个独立 vLLM 副本 + nginx least_conn（E4/E4b 拓扑）
- 天花板由**注入端**决定：单客户端 ~2060 tok/s（E4b），
  四客户端聚合 3744→4565 tok/s（E22）
- 判据：聚合吞吐贴住 `4 × 单副本饱和` ≈ 4400-4800 tok/s 即副本用满

## 维度二：多客户端注入（压测面）

- 每台机器同时是"副本宿主"和"压测客户端"（SSH 隧道 → D nginx）
- 单客户端先撞 aiohttp/GIL 墙，换注入源即可兑现副本余量（E22）
- 排查顺序：吞吐不涨 → 先加客户端（注入）→ 再看副本 AICore/HBM →
  最后才考虑扩副本

## 维度三：任务级并行（实验面）

- `scripts/cluster_bench.py` 把同一实验扇出 4 节点同刻执行：
  `bench-all`（并行压测）/ `fanout`（任意命令）/ `util`（利用率采样）
- 实测 4 路并行聚合 3119 tok/s、墙钟 9.2s vs 串行 ~33s（E21）
- 跨节点同配置差异 **11%**——所有跨节点 A/B 结论必须按此误差棒打折

## 编排层：`scripts/cluster_bench.py`

| 模式 | 用途 |
|---|---|
| `bench-all` | 4 节点同刻同负载压测 + AICore%/HBM 采样 + 结果聚合 |
| `fanout --spec` | 任意 per-node 命令扇出（多客户端注入、分片评测、混合实验） |
| `util` | 纯利用率采样（验证"机器在干活"） |
| `collect` | 远端结果自动回收 |

## 利用率判读（npu-smi 两行）

```
| 7  910B2 | OK | 87.2  33 ...        ← Power(W)=87.2, Temp=33
| 0        | ...| 0   0/0  59912/65536 ← AICore%=0, HBM=59.9/65.5GB
```

- AICore% 是采样瞬时值（2s 粒度漏尖峰）；4B decode 是 memory-bound，
  峰值 40-53% 已属正常
- HBM ~60GB = 副本 KV 池（util 0.92），不是泄漏

## 剩余可挖（按价值）

1. **分片评测**：27-chunk CPU PPL 可 4 机分片（~6h→1.5h），
   `fanout` 传 chunk 区间即可
2. **混合实验矩阵**：一机跑长上下文扫描、一机跑调度器 A/B、一机跑精度，
   一次墙钟出三组数据
3. **控制面全量 soak**：E20 控制面 × E22 注入 × 4 副本，测 SLO 维持下的
   最大 goodput
